# ZCodeSkills — скиллы Vortex для ZCode

Адаптация скиллов из [ClaudeCodeSkills](../ClaudeCodeSkills/) для [ZCode](https://zcode.z.ai) — среды разработки с ИИ-агентами от Z.AI. Содержательная часть (каноны, формулы, протоколы, чек-листы) та же; изменена упаковка под загрузку скиллов в ZCode.

## Назначение

Три скилла для оценки кода и оформления ТЗ в проектах на Vortex:

| Скилл | Назначение | Триггеры |
|-------|-----------|----------|
| [code-quality](code-quality/SKILL.md) | Оценка **формы** Unity-кода по канонным формулам с архитектурным множителем. Ветки по объёму: детальный (≤3000 LOC), по подгруппам (3000–12000), частичный, субъективный обзор (>12000) | «оцени качество кода», «прогони по критериям оценки», «оцени архитектуру пакета» |
| [applied-quality](applied-quality/SKILL.md) | Оценка **поведения** кода по канону «Сценарная прочность»: нити вход→выход, повторный вход, спутанность, рекурсия. Ветки: моно (≤2000 LOC), шардинг с пересборкой графа (2000–10000), частичный | «оцени корректность пакета», «проверь на логичность / адекватность», «что рвётся в рантайме» |
| [tz-design](tz-design/SKILL.md) | Оформление ТЗ на фичу или подсистему и self-audit готового ТЗ | «сделай ТЗ», «оформи как ТЗ», «проанализируй ТЗ», «оцени ТЗ на полноту» |

Вне набора: `vortex-layer-detect` и `vortex-initial-architecture` для ZCode не адаптированы — они есть только в ClaudeCodeSkills.

## Зависимости

- **ZCode** с поддержкой скиллов (папка со `SKILL.md`).
- **Исходник** — [ClaudeCodeSkills](../ClaudeCodeSkills/): канон у наборов общий, этот набор — его адаптация (см. «Жизненный цикл»).
- Для оценки кода: `Критерии_оценки_кода_Unity.md` содержится в `code-quality` инлайн, отдельно подключать не нужно.

## Использование

### Установка

ZCode загружает скиллы из папок со `SKILL.md`:

| Уровень | Путь | Когда использовать |
|---------|------|-------------------|
| User | `~/.zcode/skills/<skill-name>/` | На все проекты пользователя |
| Project | `<project-root>/.zcode/skills/<skill-name>/` | Только в этом проекте (коммитится в репозиторий) |

Копировать **папку скилла целиком** — вместе с `references/`:

```bash
# User-level
cp -r Vortex/AITools/ZCodeSkills/code-quality ~/.zcode/skills/
cp -r Vortex/AITools/ZCodeSkills/applied-quality ~/.zcode/skills/
cp -r Vortex/AITools/ZCodeSkills/tz-design ~/.zcode/skills/

# Project-level
mkdir -p .zcode/skills
cp -r Vortex/AITools/ZCodeSkills/*/ .zcode/skills/
```

Если версия ZCode ищет скиллы в другой папке — путь указан в настройках скиллов ZCode.

### Когда какой скилл

```
Концепция фичи
  └─► tz-design            (ТЗ и его self-audit)
        └─► (написать код)
              ├─► code-quality      (ФОРМА: метрики, паттерны, связность — код «в покое»)
              └─► applied-quality   (ПОВЕДЕНИЕ: нити, повторный вход, спутанность — код «в движении»)
```

`code-quality` и `applied-quality` меряют разное и не дублируют друг друга; полная картина по пакету — оба прогона. Триггеры у них похожи, поэтому каждый на старте подтверждает направление: «качество / архитектура / метрики» → `code-quality`, «корректность / логичность / адекватность / что рвётся» → `applied-quality`. При неоднозначной формулировке скилл задаёт один уточняющий вопрос.

## Устройство

```
ZCodeSkills/
├── code-quality/
│   ├── SKILL.md                         # Триггер, замер LOC, развилка веток, итоговая формула
│   └── references/
│       ├── detailed-canon.md            # Ветка A: порядок чтения, формулы категорий 1–4, маркеры, grep'ы
│       └── sharding-and-partial.md      # Ветки A+ (подгруппы), B (частичный), C (обзор)
├── applied-quality/
│   ├── SKILL.md                         # Триггер, замер LOC, модель нити, формула, формат вывода
│   └── references/
│       ├── axes.md                      # Оси 1/2/3/5, ступенчатость, спутанность, ярус катастроф
│       └── sharding.md                  # Ветки A+ (шардинг с пересборкой графа) и B
└── tz-design/
    ├── SKILL.md                         # Фазы, структура документа, калибровка зрелости
    └── references/
        ├── phase2-decomposition.md      # Декомпозиция данных: атомарность, реестры, инварианты
        └── self-audit.md                # Протокол аудита готового ТЗ
```

- **Основной файл и справочники.** `SKILL.md` держит протокол и развилки; подробные каноны вынесены в `references/`. Скилл читает нужный справочник **целиком** на указанном шаге — работа по памяти запрещена текстом скилла.
- **Frontmatter.** Помимо `name` и `description` — поле `when_to_use` с триггерами. `description` описывает суть скилла, `when_to_use` — фразы запуска и разграничение с близнецом.
- **Делегирование.** Указания о подагентах (`Agent`, `subagent_type`, модели haiku/sonnet) сохранены из исходных скиллов. Если в ZCode нет эквивалента с выбором модели, эти шаги выполняет основной агент — содержание анализа не меняется.

## Отличия от ClaudeCodeSkills

| | ClaudeCodeSkills | ZCodeSkills |
|---|---|---|
| Платформа | Claude Code | ZCode |
| Состав | 5 скиллов | 3 скилла (без `vortex-layer-detect`, `vortex-initial-architecture`) |
| Упаковка | один `SKILL.md` на скилл | `SKILL.md` + `references/` |
| Триггеры | в `description` | отдельное поле `when_to_use` |
| Установка | `~/.claude/skills/`, `.claude/skills/` | `~/.zcode/skills/`, `.zcode/skills/` |
| Канон | исходный | тот же |

## Жизненный цикл

Папка `Vortex/AITools/ZCodeSkills/` — источник истины для ZCode-версии. При изменении скилла:

1. Внести правку канона в **оба** набора — ClaudeCodeSkills и ZCodeSkills (для ZCode — в `SKILL.md` или в соответствующий файл `references/`).
2. Пересинхронизировать установленную копию в `~/.zcode/skills/<name>/` или `.zcode/skills/<name>/`.

Скиллы версионируются вместе с Vortex через git-историю папки.

## Граничные случаи

- **Скопирован только `SKILL.md`.** Без `references/` скилл не найдёт канон на нужном шаге. Копировать папку целиком.
- **Расхождение наборов.** Правка, внесённая только в ClaudeCodeSkills, в ZCode-версию не попадает, и оценки двух платформ начнут расходиться.
- **Правка `description` / `when_to_use`.** Эти поля определяют, когда ZCode запускает скилл; изменение формулировок меняет распознавание.
- **Нужен `vortex-layer-detect` / `vortex-initial-architecture`.** Для ZCode не адаптированы — использовать версии из ClaudeCodeSkills в Claude Code либо адаптировать по образцу этого набора.
