# NetworkSystem Mock (Unity)

**Namespace:** `Vortex.Unity.NetworkSystem.Mock`
**Сборка:** `ru.vortex.unity.networksystem.mock`
**Статус:** экспериментальный — API и формат правил могут меняться без сохранения совместимости.

## Назначение

Мок-драйвер сетевого модуля: вместо сети отвечает настроенными правилами. Нужен, чтобы без сервера проверить:
- офлайн;
- ошибки сервера;
- медленную сеть;
- повторы («503, 503, 200»);
- обновление токена («401 → 200»);
- лимиты.

Логика ядра (ТЗ-1) одинакова с любым драйвером.

## Условная компиляция

- Сборка компилируется всегда. Драйвер, ассет, модели и логика — под `#if UNITY_EDITOR || DEVELOPMENT_BUILD`.
- **В релизе типа драйвера мока нет.** Если в DriverConfig выбран мок, драйвер не подключится, и первый запрос даст fast-fail «сеть не инициализирована».
- **`MockNetworkPanel` существует в любой сборке:** Missing Script не возникает, но в релизе его методы пустые.
- **`MockNetworkSettings`** — ассет в `Resources/Settings`. В релизе его тип отсутствует, ассет остаётся без скрипта. На работу это не влияет.

## Правила (`MockNetworkSettings`)

- **Реакция по умолчанию** — для запросов без подходящего правила: 404 и предупреждение «нет правила».
- **Правила** проверяются сверху вниз. Поля правила:
  - идентификатор — для панели, непустой и уникальный;
  - включено;
  - маска URL (`[MaskSelector]`, адрес `схема://хост[:порт]/путь`);
  - метод — любой или конкретный;
  - **последовательность реакций**: попытка `n` запроса получает реакцию `n`, после конца — последнюю; повтор после 401 тоже считается;
  - процент случайных отказов — даёт транспортную ошибку.
- **Реакция:**
  - вид: ответ / транспортная ошибка / не отвечать (до таймаута ядра);
  - код, заголовки;
  - тело: `TextAsset` или текст;
  - задержка (по умолчанию 0.1 с);
  - длительность передачи — прогресс плавно идёт 0 → 1.
- **Ошибки правил** — fail-fast при инициализации: пустой или повторяющийся идентификатор, невалидная маска, нет реакций, код вне 100…599.

## Панель (`MockNetworkPanel`)

`MonoBehaviourSingleton` с публичными методами для `UnityEvent`. UI собирается из кнопок `UIComponent` + `SetActionComponent`.

| Метод | Действие |
|---|---|
| `SetOffline(bool)`, `ToggleOffline()` | все запросы — транспортная ошибка |
| `SetLatencyMultiplier(float)` | множитель задержек и передачи |
| `EnableRule(string)`, `DisableRule(string)` | включить или выключить правило поверх ассета |
| `ForceStatus(int)` | все запросы — этот код с пустым телом |
| `ForceTransportError()` | все запросы — транспортная ошибка |
| `ClearForced()` | снять принудительные код и ошибку |
| `ResetAll()` | сбросить всю подкрутку |

- **Приоритет:** офлайн → принудительная ошибка → принудительный код → правила → реакция по умолчанию.
- **Подкрутка** живёт только в текущем запуске, в ассет не пишется.
- **Активный драйвер не мок** — методы пишут предупреждение и ничего не меняют.

## Возможности

- Все возможности `true`, неустанавливаемых заголовков нет.
- Признак доступности сети — «не офлайн».
- Отладочный лог (`DebugSettings → networkLogs`) показывает, какое правило ответило и на какой попытке.
