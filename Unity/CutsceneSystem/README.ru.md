> ⚠️ **Экспериментальный пакет.** Не прошёл обкатку в продуктовой эксплуатации. Публичное API `CutsceneBus` и контракт префаба контента могут измениться без обратной совместимости. Вместе с ним экспериментальны пакеты-спутники: [NaniExtensions/CutsceneSystem](../../NaniExtensions/CutsceneSystem/README.ru.md), [SpineExtensions/Cutscenes](../../SpineExtensions/Cutscenes/README.ru.md), [Sdk/CutsceneSystem](../../Sdk/CutsceneSystem/README.ru.md).

**Namespace:** `Vortex.Unity.CutsceneSystem.*`
**Сборка:** `ru.vortex.unity.cutscene`

## Назначение

Показ катсцены как прохода по графу состояний. Чем показан узел графа, пакет не знает: это может быть Spine, смена спрайтов или что угодно ещё, собранное в префабе контента.

- **Ход показа — граф катсцены.** Узлы и переходы описывает запись [`StateGraph`](../../Core/StateGraphSystem/README.ru.md) в базе данных; у каждой катсцены свой граф. Узел показывается состоянием `UIStateSwitcher` с тем же именем. Граф может ветвиться: переходы выбираются по условиям или по сигналу «дальше».
- **Граф держит и показывает контент.** На корне префаба контента — [`StateGraphView`](../StateGraphSystem/README.ru.md): он берёт копию графа из базы и переключает свитчер. Оркестратор подаёт графу сигналы и закрывает показ, когда граф дошёл до конечного узла.
- **Контент — подгружаемый префаб.** Он в памяти только на время показа.
- **Одна шина обращений** `CutsceneBus`: открыть, дальше, выставить узел, пропустить. Шина ничего не исполняет: она передаёт обращение оркестратору сцены и хранит данные показа.
- **Всё делает оркестратор.** Обращение он запоминает, а исполняет на своём `LateUpdate`. Обращения и события никогда не исполняются вложенно друг в друга.
- **Прерывание — немедленное закрытие** показа.

Вне ответственности:

- **Чем показан узел и чем он озвучен.** Это содержимое префаба: элементы `UIStateSwitcher`, хэндлеры `AudioAdvancedControl`, Spine-хэндлеры из `SpineExtensions`.
- **Сам граф.** Его структура, проверка и редактор — пакет [`StateGraphSystem`](../StateGraphSystem/README.ru.md).
- **Кто запускает катсцену.** Сценарий, UI или игровая логика вызывают `CutsceneBus` сами; команды Naninovel лежат в `NaniExtensions/CutsceneSystem`.
- **Сохранение.** Состояние показа в сейв не входит.
- **Пауза.** Заморозка визуала и звука — дело хэндлеров контента.

## Использование

### 1. Граф катсцены

Запись `Database/State Graph` (см. [StateGraphSystem](../StateGraphSystem/README.ru.md)):

- узел на каждую фазу катсцены и конечный узел `End` без переходов;
- фаза, ждущая команды, переходит дальше «по `Next`»;
- фаза с автопереходом тоже переходит «по `Next`»: сигнал подаёт сам контент (см. «Сигнал «дальше»»);
- ветвление — несколько переходов с условиями; приоритет — порядок переходов в узле.

Граф правится в визуализаторе. Префабы и графы катсцен умеет создавать [фабрика ассетов](../../../Plugins/AssetFactory/README.ru.md).

### 2. Префаб контента

- На корне — `StateGraphView`: граф катсцены, свитчер контента, режим `Restart`. Для контента, где смена узла — переход на твинах (смена спрайтов), задаётся `switchDelay` (см. «Задержка переключения контента»).
- Если в катсцене есть автопереходы — на корне ещё `CutsceneContentHandler`: через него контент подаёт сигнал «дальше».
- `UIStateSwitcher`: по состоянию на каждый узел графа, с тем же именем, включая пустое состояние `End`.
- Визуал и звук узла — элементы и объекты его состояния.
- В узле с автопереходом — источник сигнала: вызов `CutsceneContentHandler.Next()` из состояния (`EventFire`) либо профильный хэндлер (для Spine — `SpineCutsceneAutoNext`). Профильный хэндлер на время узла запирает замок «дальше» (см. «Замок «дальше»»).

Готовые основы префаба контента лежат слоем выше, потому что звук в них — хэндлеры SDK:

- спрайтовая катсцена — [`Sdk/CutsceneSystem/Example`](../../Sdk/CutsceneSystem/README.ru.md);
- Spine-катсцена — [`SpineExtensions/Cutscenes/Example`](../../SpineExtensions/Cutscenes/README.ru.md).

### 3. Оркестратор на сцене

Объект с `CutsceneOrchestrator`:

| Поле | Назначение |
|---|---|
| `cutscenes` | индекс: ключ катсцены и хэндл префаба её контента. Ключи не повторяются: при повторе редактор предупреждает, открывается первая запись |
| `switcher` | свитчер состояний оркестратора: Off / Loading / On |
| `target` | куда ставится контент; не задано — под сам оркестратор |

### 4. Команды

```csharp
CutsceneBus.Open(key);         // открыть; ключ — ключ записи в индексе оркестратора
CutsceneBus.Next();            // дальше: сигнал Next графу; вход в конечный узел — закрытие
CutsceneBus.SetNode("Final");  // выставить узел — по имени или Id
CutsceneBus.Skip();            // пропустить — закрыть сразу

CutsceneBus.OnShowStarted  += key => { };   // показ начался: контент загружен, граф показывает первый узел
CutsceneBus.OnShowFinished += key => { };   // показ завершён либо не состоялся
```

Обращение исполняется не в момент вызова, а на ближайшем `LateUpdate` оркестратора. События приходят после этого.

## Архитектура

```
Bus/
  CutsceneBus (static)             — слот оркестратора, передача обращений, данные и события показа

Models/
  CutsceneControl                  — управляющие данные показа: имя текущего узла
  CutsceneStageState               — состояния оркестратора: Off / Loading / On

Handlers/
  CutsceneOrchestrator             — приём обращений и весь показ: загрузка, сигналы графу, закрытие
  CutsceneContentHandler           — источник автоперехода: сигнал «дальше» с Id показанного узла;
                                     проводник замка «дальше» для профильных хэндлеров

UIConditions/
  NoneCutscene                     — условие интерфейса: открыт без катсцены (с Invert — только во время неё)
```

### Шина и оркестратор

Зависимость односторонняя: оркестратор знает шину, шина об оркестраторе — только то, что слот занят.

| Что есть на шине | Назначение |
|---|---|
| Слот | держатель один; пока слот занят, второй претендент отклоняется |
| Обращения | `Open`, `Next`, `Next(узел)`, `SetNode`, `Skip`. Шина сразу передаёт их держателю слота событием и больше о них не помнит |
| Данные показа | имя текущего узла (`Control`). Пишет держатель слота |
| Замок «дальше» | `IsLocked`: узел с автопереходом доигрывает. Берут и отпускают источники автоперехода; оркестратор замок не читает |
| События показа | `OnShowOpening`, `OnShowStarted`, `OnShowFinished`. Рассылает держатель слота |

Сама шина делает одно: отклоняет открытие, пришедшее при пустом слоте. Оркестратора она не ждёт: ошибка в лог сразу, `OnShowFinished(ключ)` — в конце кадра. Событие отложено, чтобы подписчик, открывающий катсцену заново на каждый отказ, не ушёл в бесконечную рекурсию. Отложенное событие рассылает `TimeController`: без него на сцене оно не придёт.

Подписчики событий шины сбрасываются при запуске игры (`SubsystemRegistration`). Подписываться нужно после этого момента — например, в `OnEnable`.

### Обращения и их исполнение

В момент прихода обращения оркестратор только запоминает просьбу:

| Обращение | Что запоминается | Когда не принимается |
|---|---|---|
| `Open(ключ)` | «просили открыть» и ключ. Прежняя, ещё не исполненная просьба открытия вытесняется и получит `OnShowFinished`; просьбы о ходе прежнего показа отменяются | — |
| `Next()` | «просили дальше» | показ ещё не запущен (контент грузится); ждёт исполнения открытие, пропуск либо закрытие по концу графа |
| `Next(узел)` | «просили дальше» | то же, и вдобавок узел не совпадает с текущим узлом графа |
| `SetNode(узел)` | «просили узел» и его Id или имя; более поздняя просьба заменяет прежнюю. Пришла, пока катсцена открывается, — ждёт старта показа | катсцены нет и не открывается; ждёт исполнения пропуск; пустое имя (ошибка в лог) |
| `Skip()` | «просили пропустить». Неисполненная просьба открытия отменяется и получит `OnShowFinished` | — |

Вход графа в конечный узел (`OnFinished`) тоже только запоминается: «граф завершён».

Исполняет оркестратор на своём `LateUpdate`, всегда в одном порядке:

1. **Пропуск, открытие поверх идущей катсцены либо завершённый граф** — идущая закрывается, рассылается её `OnShowFinished`.
2. **Несостоявшиеся открытия** получают `OnShowFinished` — те, что накопились к этому шагу. Отказ, порождённый обработчиком этого события, ждёт следующего прохода.
3. **Открытие** — отказ (`OnShowFinished(ключ)`) либо начало загрузки и `OnShowOpening(ключ)`.
4. **Результат загрузки** — создаётся контент; его `StateGraphView` берёт копию графа и запускает её со стартового узла; узел, попрошенный во время загрузки, выставляется вместо стартового; `OnShowStarted(ключ)`.
5. **Ход графа** — выставление узла, а если его не просили — «дальше» (`Next` графу).
6. **Граф дошёл до конца** на этом проходе — показ закрывается тут же. Проверка идёт дважды: сразу после запуска показа (узел, попрошенный во время загрузки, оказался конечным) и после хода графа.

Правила:

- **Одна просьба «дальше» на узел.** Просьба держится до исполнения; повторные до этого момента ничего не добавляют. Игрок нажмёт ещё раз, автопереход сработает для своего узла сам.
- **Ход графа — только то, что просили до прохода.** Просьба, пришедшая во время исполнения (например, автопереход из состояния только что показанного узла), исполняется следующим кадром.
- **Ход графа — только для своей катсцены и только после старта показа.** «Дальше» до старта игнорируется; выставление узла до старта ждёт его и применяется вместо стартового узла. Просьба, принятая для одной катсцены, на другую не переходит.
- **Выставление узла точнее «дальше».** Пришли оба за один проход — исполняется выставление.
- **Переходы по условиям** граф делает сам, в любой момент: оркестратор узнаёт о них из текущего узла графа и о конце графа — из `OnFinished`.
- **Без вложенности.** Обработчик события может обращаться к шине: просьба запоминается и исполняется позже — в том же проходе, если её шаг ещё впереди, иначе в следующем кадре.
- **Сбой не останавливает проход.** Исключение на шаге пишется в лог; остальные шаги исполняются.
- **Порядок шагов постоянный**, а не порядок прихода. Разница видна, только когда в одном кадре пришли разные обращения: `Skip` после `Open` отменяет это открытие; `Open` после `Skip` — исполняются оба.

### Поток

```
CutsceneBus.Open(key)                       — шина передаёт просьбу оркестратору, тот её запоминает
    ↓ (LateUpdate оркестратора)
[Оркестратор] идущая катсцена закрывается, OnShowFinished(её ключ)
    ↓
[Оркестратор] ключ в индексе
    └── свитчер → Loading, OnShowOpening(key), загрузка префаба
    ↓ (загрузка завершена; ближайший LateUpdate)
[Оркестратор] экземпляр под target
    ├── StateGraphView берёт копию графа и показывает стартовый узел
    ├── свитчер → On
    ├── узел, попрошенный во время загрузки, — вместо стартового
    └── OnShowStarted(key)
    ↓
[Оркестратор] подаёт сигналы графу
    ├── CutsceneBus.Next()          — команда извне → Next
    ├── CutsceneBus.Next(узел)      — автопереход от контента → Next
    └── CutsceneBus.SetNode(узел)   — прямой переход → ForceNode
[Граф]        переходы по условиям — сам
    ↓ … следующие узлы …
[Граф] вход в конечный узел → OnFinished
    ↓ (LateUpdate оркестратора)
[Оркестратор] выключает и уничтожает экземпляр, отпускает префаб, свитчер → Off
    ├── имя узла → пусто
    └── OnShowFinished(key)
```

### Узлы

- **Граф берётся из контента** при старте показа: копию держит `StateGraphView` корня. Нет `StateGraphView`, граф не получен (записи нет, база не загружена) или не запустился (ошибки графа) — показ закрывается с ошибкой в лог.
- **«Дальше»** — сигнал `Next` графу: он выбирает первый по порядку переход «по `Next`» с выполненными условиями. Не нашлось — реакция узла по его настройке (молча, предупреждение, ошибка), узел не меняется.
- **Конец** — вход в узел без переходов: показ закрывается. `StateGraphView` переключает свитчер в состояние этого узла (`End`), но на экран оно почти не попадает: после `Next` либо `SetNode` показ закрывается в том же проходе, до отрисовки кадра, после перехода по условиям — на ближайшем. Состояние нужно, чтобы View не писал ошибку о недостающем состоянии.
- **Выставление узла** — по Id или имени, минуя условия. Неизвестный узел — ошибка в лог от графа, узел не меняется. Текущий узел — ничего не происходит.

### Сигнал «дальше»

Сигнал один, источников два:

- `CutsceneBus.Next()` — команда извне. Узла она не несёт и узел не проверяет: принимается в любом узле запущенного показа.
- `CutsceneBus.Next(узел)` — автопереход от контента. Контент называет Id узла, который показывает; сигнал принимается, только если граф стоит на этом же узле. Проверка идёт в момент прихода обращения.

Защиты от дребезга нет: каждая команда, пришедшая на отдельном проходе оркестратора, двигает граф. Порядки сигналов:

- Автопереход сработал, следом на другом проходе пришла команда — она уводит граф и с нового узла. Пришли за один проход — сливаются в один сигнал.
- Команда пришла, следом сработал автопереход прошлого узла (пока контент догоняет показ) — сигнал назван старым узлом и не принимается.

Команды, идущие подряд быстрее прохода оркестратора, сливаются (см. «Одна просьба «дальше» на узел»). Источник, которому важна каждая команда, выдерживает между ними паузу хотя бы в кадр — так делает команда сценария `@cutscene_Next`.

Хэндлер контента подставляет узел сам: источник автоперехода зовёт `CutsceneContentHandler.Next()`, тот берёт Id показанного узла у `StateGraphView`. Вызов от выключенного контента игнорируется: его показ закрыт, и отложенный сигнал (твин, таймер) не должен попасть в следующую катсцену.

### Замок «дальше»

Команда извне, пришедшая, пока узел с автопереходом ещё доигрывает, увела бы граф с этого узла вместо следующего: при промотке текста катсцена отстала бы на узел. Замок позволяет источнику команд дождаться автоперехода.

- **Держатели.** Замок заперт, пока его держит хотя бы один держатель (`CutsceneBus.IsLocked` — реактивное `BoolData` мультизамка `MultiLock` из `ReactiveValues`). Брать и отпускать его — `internal` у шины; снаружи пакета — через `CutsceneContentHandler.Lock(держатель)` / `Unlock(держатель)`. Повторный захват тем же держателем ничего не добавляет.
- **Кто держит.** Источник автоперехода: берёт замок на включении, отпускает при срабатывании и на выключении. `SpineCutsceneAutoNext` делает так сам; вызов `CutsceneContentHandler.Next()` из `EventFire` замок не берёт.
- **Кто читает.** Источник команд, которому важно не перебить узел, — например, команды сценария `@cutscene_Play` и `@cutscene_Next`: они ждут, пока замок откроется. Оркестратор и шина «дальше» при запертом замке не отклоняют.
- **Порядок.** Источник отпускает замок и тут же подаёт сигнал; оркестратор исполняет его на ближайшем проходе. Читатель, проверяющий замок в конце кадра, видит его открытым уже после исполнения автоперехода — его команда с автопереходом не сольётся.
- **Время.** Замок держится, пока узел доигрывает, — по тому времени, по которому идёт контент. Spine-скелет идёт по игровому времени, поэтому при ускорении (`Time.timeScale`, промотка Naninovel) узел и замок кончаются раньше.
- **Конец показа.** Контент выключается при закрытии — держатели отпускают замок на выключении. Сброс при запуске игры очищает замок вместе со статикой шины.

### События показа

| Событие | Когда |
|---|---|
| `OnShowOpening(ключ)` | открытие принято оркестратором, началась загрузка контента |
| `OnShowStarted(ключ)` | контент загружен, граф показывает первый узел |
| `OnShowFinished(ключ)` | показ закрыт либо не состоялся: отказ открытия, сбой загрузки, отмена |

- **Ключ катсцены** — параметр события: подписчик отличает свою катсцену от чужой.
- **Порядок для одной катсцены:** `OnShowOpening` → `OnShowStarted` → `OnShowFinished`. За `OnShowOpening` всегда приходит `OnShowFinished` с тем же ключом, поэтому по этой паре можно вести признак «катсцена открыта», включая загрузку. Отклонённое открытие даёт только `OnShowFinished`.
- **Рассылает оркестратор, когда состояние приведено в порядок:** `OnShowFinished` — после выгрузки контента, `OnShowStarted` — после запуска графа.
- **`IsActive`** истинно с момента обращения `Open` и до рассылки её `OnShowFinished`. Если катсцену закрыло открытие новой, то в обработчике `OnShowFinished` прежней `IsActive` истинно.
- **Обращения из обработчика** запоминаются и исполняются позже (см. «Без вложенности»).
- **Подписчики изолированы.** Исключение одного пишется в лог (со стеком) и остальным не мешает. После исключения подписчика `OnShowOpening` либо `OnShowStarted` катсцена прерывается — как по `Skip`, в следующем кадре.
- **`OnShowStarted` не рассылается**, если запуск сорвался (исключение контента при создании либо на входе в узел).

### Задержка переключения контента

Для контента, где смена узла — переход на твинах, у `StateGraphView` задаётся `switchDelay`. Если следующее состояние выставить посреди перехода, он оборвётся и кадр даст скачок яркости.

- Следующее состояние выставляется не раньше, чем через `switchDelay` после предыдущего.
- Узлы, пришедшие во время ожидания, не копятся: по его окончании показывается сразу последний. Прыжок через несколько узлов промежуточных не показывает.
- Первый узел показывается сразу: до него переходов не было.
- Время считается без учёта `Time.timeScale` — как и у твинов.
- Задержка действует только на показ: граф переходит без ожидания.
- Автопереход от состояния, которое контент показывает с опозданием, не принимается: граф с этого узла уже ушёл.
- View и твины друг о друге не знают. Согласовать `switchDelay` с длительностью твинов — дело верстальщика.

### Прерывание

`Skip` закрывает показ сразу — на ближайшем проходе оркестратора: контент выгружается, рассылается `OnShowFinished`. Пока контент ещё грузится, `Skip` отменяет загрузку.

### Условие интерфейса

`NoneCutscene` — условие для пресета интерфейса (`UserInterfacePreset`, массив `Conditions`, пакет `UIProviderSystem`).

| Поле | Значение |
|---|---|
| `invert` выключен (по умолчанию), надпись `NoneCutscene` | интерфейс открыт, пока катсцены нет; закрыт, пока она открывается или идёт |
| `invert` включён, надпись `ActiveCutscene` | наоборот: открыт только на время катсцены — например, кнопка пропуска |

- Источник — `CutsceneBus.IsActive`: истинно с обращения `Open` до рассылки его `OnShowFinished`.
- Перепроверка — по `OnShowOpening` и `OnShowFinished`. Интерфейс меняет состояние в кадре, когда оркестратор принял открытие, и после выгрузки контента; отклонённое открытие перепроверяется по своему `OnShowFinished`.
- Закрытие у провайдера интерфейсов приоритетнее открытия: «закрыт» этого условия перекрывает «открыт» других условий того же пресета.

### Выключение оркестратора

На `OnDisable` оркестратор отписывается от обращений и сразу освобождает слот. Показ его не переживает:

- **Идущий показ** закрывается сразу, `OnShowFinished` рассылается тут же; загрузка отменяется.
- **Неисполненные просьбы** открытия получают `OnShowFinished`.

Слот свободен с момента выключения: другой оркестратор может занять его сразу. Оркестратор, включённый обратно, занимает слот заново.

## Контракт

### Гарантии

- **Катсцена одна.** Открытие новой сначала закрывает идущую; её `OnShowFinished` рассылается до начала открытия новой.
- **Без вложенности.** Обращение и конец графа запоминаются и исполняются на `LateUpdate` оркестратора.
- **Один `OnShowFinished(ключ)` на каждое обращение `Open`.** `OnShowOpening(ключ)` и `OnShowStarted(ключ)` — не больше одного каждое и всегда раньше, в этом порядке.
- **Одна просьба «дальше» — один сигнал графу.** Первая принятая просьба в узле исполняется, повторные до её исполнения не действуют.
- **Закрытие одно.** Все пути — конец графа, пропуск, сбой, выключение оркестратора — проходят через одно место: контент выгружается, данные показа сбрасываются, рассылается событие.
- **Контент выгружается** при закрытии показа и при выключении оркестратора. Он выключается сразу, не дожидаясь уничтожения в конце кадра: условия графа гаснут вместе с `StateGraphView`, а отложенные сигналы контента в следующий показ не попадут.
- **Имя узла пишется в одном месте.** `CutsceneControl` закрыт ключом владельца шины; узел сообщает держатель слота.
- **Сигналы привязаны к показу и узлу.** Просьба о ходе графа для одного показа и автопереход от уже пройденного узла на идущий показ не действуют.
- **Устаревшая загрузка ни на что не влияет.** Результат отменённой загрузки — и успех, и сбой — отбрасывается.
- **Шина не зависит от оркестратора.** Она знает только, что слот занят.

### Дисциплина

- **Катсценой управляет один источник.** Пакет рассчитан на одну несостязательную систему воспроизведения: сценарий, UI либо игровая логика ведут катсцену по очереди, а не наперебой. Обработчики событий показа, которые в ответ на событие сами открывают, пропускают или двигают катсцены и этим перебивают друг друга, — вне штатного использования (см. «Ограничения»).
- **Оркестратор один.** Слот шины единственный; второй оркестратор отклоняется с ошибкой.
- **Ключи индекса не повторяются.**
- **На корне префаба контента — `StateGraphView`** с графом катсцены в режиме `Restart`; у свитчера — по состоянию на каждый узел графа, с тем же именем.
- **У графа есть конечный узел**, иначе показ закрывается только пропуском.
- **Источник автоперехода стоит только в узлах с автопереходом**, и у таких узлов переход «по `Next`».

### Ограничения

- Результат обращения виден не сразу после вызова, а после `LateUpdate` оркестратора.
- Префаб, загрузка которого завершается сразу (прямая ссылка, прогретый кэш), запускается в том же проходе, что и открытие: состояние `Loading` тогда не доживает до конца кадра.
- Граф запускается со стартового узла при создании контента. Узел, попрошенный во время загрузки, выставляется следом в том же кадре: стартовый узел успевает войти и выйти (его условия запускаются и гасятся).
- Разные обращения одного кадра исполняются в порядке шагов, а не в порядке прихода.
- Состязательные обращения из обработчиков событий показа не поддерживаются. Примеры того, что тогда возможно:
  - обработчик `OnShowFinished` зовёт `Skip` ровно в момент, когда открытие, пришедшее из другого обработчика, закрывает идущую катсцену, — открытие получает два `OnShowFinished` (один с пустым ключом и ошибкой «пустой ключ» в логе), и `IsActive` может стать ложным при идущем показе;
  - `OnShowFinished` отклонённого открытия приходит кадром позже, уже после `OnShowOpening` другой катсцены, — подписчик, который ведёт признак «катсцена открыта» по этой паре без сверки ключа, закроет его раньше времени;
  - исключение одного подписчика прерывает катсцену и вместе с ней отменяет открытие, запрошенное другим подписчиком.
- Перезапустить текущий узел через `SetNode` нельзя: выставление того же узла ничего не делает.
- Ключ в событии не различает два показа одной и той же катсцены подряд.
- Команда «дальше» узел не проверяет: при частых командах показ может уйти вперёд спрайтового контента и закрыться раньше, чем тот покажет последние узлы.
- Отклонённый второй оркестратор сам слот не займёт, когда первый уйдёт, — его нужно включить заново.
- Если оркестратор выключить из его собственного состояния `Loading` или `On`, его свитчер может остаться в этом состоянии до следующего включения: вложенную установку `Off` свитчер не принимает и пишет об этом ошибку в лог.
- `target` должен быть активен: `StateGraphView` берёт граф на `OnEnable`, и под выключенным родителем граф не получен — показ закрывается с ошибкой.

## Граничные случаи

| Ситуация | Поведение |
|---|---|
| `Open` с пустым ключом | `Debug.LogError`, `OnShowFinished(ключ)` |
| `Open` при пустом слоте | `Debug.LogError` сразу, `OnShowFinished(ключ)` в конце кадра. Оркестратор, включившийся позже в том же кадре, это открытие не получит |
| Подписчик `OnShowFinished` открывает катсцену на каждое событие | не больше одного открытия за кадр: отказ, порождённый обработчиком, рассылается следующим проходом |
| Ключа нет в индексе, не задан префаб | `Debug.LogError`, `OnShowFinished(ключ)` |
| Ключ повторяется в индексе | предупреждение в редакторе; открывается первая запись |
| `Open` при идущей катсцене | прежняя закрывается (`OnShowFinished`), затем в том же проходе начинается загрузка новой |
| `Open` во время загрузки прежней | загрузка отменяется (`OnShowFinished`), затем начинается загрузка новой |
| Два `Open` за кадр | открывается последняя; первая получает `OnShowFinished` |
| `Open`, затем `Skip` в одном кадре | открытие отменяется (`OnShowFinished`); идущая катсцена закрывается |
| `Open` из обработчика события показа | запоминается; исполняется в том же проходе, если шаг открытия ещё впереди, иначе в следующем кадре |
| Оркестратор выключен, пока он запускает показ (из `Awake` контента, его хэндлеров, состояний свитчера) | запуск прекращается, контент убирается, `OnShowFinished(ключ)` |
| Сбой загрузки префаба, пустой префаб, нет `StateGraphView` на корне, граф не получен или не запустился | `Debug.LogError`, контент выгружается, `OnShowFinished(ключ)` |
| Исключение при запуске показа (создание контента, вход в узел) | исключение в лог, показ закрывается, `OnShowFinished(ключ)`; `OnShowStarted` не рассылается |
| Загрузка завершилась после отмены, в том числе сбоем | результат отбрасывается, идущий показ не затрагивается |
| `Next` / `SetNode` / `Skip` без открытой катсцены, `Next` до старта показа | ничего |
| `Next` в узле без подходящего перехода «по `Next`» | реакция узла по его настройке (молча / предупреждение / ошибка), узел не меняется |
| `Next` ведёт в конечный узел | показ закрывается в том же проходе, `OnShowFinished(ключ)` |
| Граф дошёл до конечного узла по условиям | показ закрывается на ближайшем проходе |
| `SetNode` во время загрузки | применяется при старте показа вместо стартового узла |
| `SetNode` с пустым именем | `Debug.LogError`, просьба не запоминается |
| `SetNode` с неизвестным узлом | ошибка в лог от графа, узел не меняется |
| `SetNode` с текущим узлом | ничего |
| `SetNode` на конечный узел | показ закрывается |
| `SetNode` и `Next` за один проход | исполняется `SetNode` |
| Ход графа принят, а в том же проходе катсцену сменила другая | просьба пропадает, новая катсцена стартовый узел не проскакивает |
| Несколько `Next` за кадр из любых источников | один сигнал графу |
| `Next(узел)` с узлом, с которого граф уже ушёл | не принимается |
| `CutsceneContentHandler.Next()` от выключенного контента | игнорируется |
| `Next` при запертом замке | принимается: замок читают источники команд, шина и оркестратор его не проверяют |
| Источник автоперехода не дождался конца узла (анимация не доигрывает) | замок заперт, пока источник не выключат — обычно до смены узла либо закрытия показа |
| `Skip` во время загрузки | загрузка отменяется, `OnShowFinished(ключ)` |
| `Skip` дважды за кадр | один пропуск |
| Исключение в подписчике события показа | в лог; остальные подписчики событие получают; после `OnShowOpening` либо `OnShowStarted` катсцена прерывается в следующем кадре |
| Исключение контента при смене узла | в лог; показ продолжается |
| В свитчере нет состояния узла | ошибка в лог от `StateGraphView`, показ не меняется |
| Оркестратор выключен посреди показа | показ закрывается в момент выключения, контент выгружается, слот освобождён |
| Оркестратор выключен контентом при выгрузке | показ уже закрывается; повторного закрытия нет |
| Оркестратор выключен с неисполненной просьбой открытия | `OnShowFinished(ключ)` |
| Второй оркестратор | `Debug.LogError`, не регистрируется |
| Новый узел раньше `switchDelay` | когда задержка истечёт, показывается сразу последний узел |
| Катсцена завершена, пока контент ждёт задержку | контент выгружается, отложенное переключение не происходит |

## Публичный API

```csharp
namespace Vortex.Unity.CutsceneSystem.Bus
{
    public static class CutsceneBus
    {
        public static CutsceneControl Control { get; }
        public static bool IsActive { get; }      // открытие принято, контент загружается либо показ идёт
        public static BoolData IsLocked { get; }  // замок «дальше» (MultiLock): узел с автопереходом доигрывает

        public static event Action<string> OnShowOpening;    // параметр — ключ катсцены
        public static event Action<string> OnShowStarted;    // параметр — ключ катсцены
        public static event Action<string> OnShowFinished;   // параметр — ключ катсцены

        public static void Open(string key);      // ключ — ключ записи в индексе оркестратора
        public static void Next();                // команда извне
        public static void Next(string nodeId);   // автопереход от контента; nodeId — показанный узел
        public static void SetNode(string node);  // выставить узел — Id или имя
        public static void Skip();                // закрыть показ сразу
    }
}

namespace Vortex.Unity.CutsceneSystem.Models
{
    public class CutsceneControl : IReactiveData
    {
        public StringData Node { get; }           // имя текущего узла; пусто — показа нет
        public event Action OnUpdateData;         // узел изменился
    }

    public enum CutsceneStageState { Off, Loading, On }
}

namespace Vortex.Unity.CutsceneSystem.Handlers
{
    public class CutsceneOrchestrator : MonoBehaviour { }     // настраивается в инспекторе

    public class CutsceneContentHandler : MonoBehaviour
    {
        public void Next();                                   // автопереход: Id показанного узла — шине
        public void Lock(Object holder);                      // запереть замок «дальше» на время узла
        public void Unlock(Object holder);                    // отпустить замок
    }
}

namespace Vortex.Unity.CutsceneSystem.UIConditions
{
    public class NoneCutscene : UnityUserInterfaceCondition { }   // invert — в инспекторе пресета интерфейса
}
```
