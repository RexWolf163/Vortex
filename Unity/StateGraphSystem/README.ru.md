# StateGraphSystem (Unity)

**Namespace:** `Vortex.Unity.StateGraphSystem.Presets`, `.Views`, `.Editor`
**Сборки:** `ru.vortex.unity.stategraph`, `ru.vortex.unity.stategraph.editor` (Editor)

## Назначение

Unity-оснастка автомата состояний из ядра (`ru.vortex.stategraph`): пресет графа в БД, компонент показа и визуальный редактор.

- `StateGraphPreset` — пресет записи `StateGraph` (всегда `MultiInstance`), сводка в инспекторе
- `StateGraphView` — берёт свою копию графа из БД и показывает текущий узел состоянием `UIStateSwitcher`
- Sync — сверка состояний свитчера с узлами графа
- Визуализатор на UI Toolkit: правка структуры, раскладка узлов, подсветка текущего узла в Play Mode

Вне скоупа: управление автоматом (`Next` / `ForceNode` / `Stop`) — забота потребителя; логика ядра — см. README ядра.

## Пресет

`Database/State Graph` — `StateGraphPreset : RecordPreset<StateGraph>`. Хранит только структуру:

```
StateGraphPreset
├── startNode : string                         ← выбор из узлов; красный, если не задан/не найден
└── nodes     : StateNodePreset[]              [SerializeReference]
    ├── id (скрыт, создаётся при добавлении), name, nextMiss
    └── transitions : StateTransitionPreset[]  [SerializeReference]
        └── target (выбор из узлов), waitNext, conditions : Condition[] [SerializeReference]
```

- Структуру можно править и в инспекторе (группа «Structure»), и в визуализаторе.
- Пустые элементы (узел, переход или условие без типа) в модель не попадают и показываются ошибкой.
- **Сводка** в инспекторе: стартовый узел, число узлов (конечных), автопереходов, переходов по `Next`, условий; замечания проверки графа (ошибки сверху). Пересчитывается после изменения пресета.
- Кнопка **Open in visualizer** открывает граф в визуализаторе.

## StateGraphView

```csharp
var graph = view.GetData<StateGraph>();   // IDataStorage
graph.Next();
```

| Поле | Описание |
|---|---|
| `graph` | Запись графа (`DbRecord`, `MultiInstance`) |
| `onEnableBehavior` | `Restart` (по умолчанию) — каждое включение со стартового узла, при выключении условия останавливаются; `Resume` — продолжение с места остановки, условия работают и у выключенного View |
| `switcher` | `UIStateSwitcher`, состояния которого названы именами узлов |

Жизненный цикл:

- Первый `OnEnable` — ждёт загрузки БД (`Database.OnInit`), берёт копию (`GetNewRecord`), поднимает `OnUpdateLink`. Копия живёт до `OnDestroy`.
- `OnEnable` — подписка на `CurrentNode`, `Activate()`, явное обновление показа (событие могло не прийти: перезапуск на тот же узел, узел `ForceNode` из выключенного состояния).
- `OnDisable` — отписка, `Deactivate(Resume ? true : false)`.
- `OnDestroy` — `Deactivate(false)`: в Resume условия работали и у выключенного View — гасятся окончательно.

Показ: текущий узел → состояние свитчера с тем же именем. Не запущенный автомат показывается стартовым узлом, завершённый — последним показанным. Состояния нет — ошибка в лог, показ не меняется.

### Sync

Вне Play Mode инспектор View показывает списки **Missing states** (узлы без состояния) и **Extra states** (состояния без узла). Кнопка **Sync switcher states** добавляет недостающие состояния пустыми в конец и удаляет лишние (Undo). Номера состояний свитчера после удаления сдвигаются — `stateOnEnable` не корректируется.

## Визуализатор

Открытие: кнопка в инспекторе пресета или `Tools/Vortex/State Graph Visualizer` и выбор пресета в панели инструментов.

| Действие | Как |
|---|---|
| Сдвиг полотна | ЛКМ по фону или СКМ |
| Масштаб | Колесо |
| Вписать граф | `Frame all` |
| Добавить узел | `Add node` или ПКМ по фону |
| Переместить узел | Перетащить |
| Новый переход | Протянуть от кружка справа на узле к другому узлу |
| Стартовый узел, удаление узла | ПКМ по узлу |
| Переход «по Next», удаление перехода | ПКМ по переходу или его метке |
| Удалить выделенное | Delete |

- Все правки — с Undo; удаление узла удаляет и переходы на него.
- Боковая панель: выделенный узел или переход редактируется инспектором Odin (включая выбор типа условия); ниже — список замечаний, клик выделяет узел или переход.
- Обозначения: метки START / END; автопереходы — сплошные, «по `Next`» — пунктир; метка на переходе — порядок, `Next`, число условий; рамка — старт / предупреждение / ошибка / выделение.
- Переход на несуществующий узел не рисуется: его ошибка видна по рамке узла-источника, сам переход выбирается из списка замечаний.
- **Play Mode:** подсвечивается текущий узел первого выбранного `StateGraphView` этого графа, а если такой не выбран — выбранного ранее; имя View — в панели инструментов.
- **Палитра** — цвета `Graph*` в `ToolsSettings` (светлая и тёмная тема редактора).

### Раскладка

Позиции узлов — в отдельном редакторском ассете `StateGraphLayout` «{пресет} Layout» рядом с пресетом (пресет БД хранит только структуру). С пресетом связан GUID-ом его ассета: пресет сам переименовывает свой файл при смене имени, и связь не рвётся. Ассет создаётся при первом перемещении или добавлении узла. Узлы без сохранённой позиции раскладываются автоматически: столбец — расстояние от стартового узла, недостижимые — отдельным столбцом.

## Граничные случаи

| Ситуация | Поведение |
|---|---|
| View включён до загрузки БД | Копия берётся по `Database.OnInit`; повторные вкл/выкл не дублируют подписку |
| View выключен до загрузки БД | Копия берётся, `Activate` — при следующем включении |
| Запись графа не найдена | Ошибка `Database`, View ничего не показывает |
| Граф с ошибками | Ошибки ядра в лог; View показывает стартовый узел, если он есть |
| В свитчере нет состояния узла | Ошибка в лог, показ не меняется |
| Sync в Play Mode | Скрыт |
| Раскладки нет | Автоматическая раскладка; ассет создаётся при первой правке позиции |
