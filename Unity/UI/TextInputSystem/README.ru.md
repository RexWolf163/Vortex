# TextInputSystem

**Namespace:** `Vortex.Unity.UI.TextInputSystem`
**Сборка:** `ru.vortex.unity.ui.textinput`

## Назначение

Режим ввода текста с клавиатуры поверх отображаемого значения: кнопка переводит значение в ввод, поверх него появляется поле со своим фоном, Enter сохраняет, Esc откатывает. Ввод — штатный `TMP_InputField` (курсор, выделение, буфер обмена, IME, многострочность), маска — список фильтров.

Возможности:
- Не знает данных: исходный текст приходит в `Begin`, итог уходит событием `OnSave` — что с ним делать, решает владелец значения
- Маска через `[SerializeReference]`: проверка на каждый вводимый символ и при сохранении
- Ввод одновременно только в одном поле
- Завершение кликом мимо поля — через публичные `Save` / `Rollback`, которые линкуются из вёрстки (подложка)

Вне ответственности:
- Глушение игровых клавиш на время ввода. Поле читает клавиатуру само, мимо карт ввода, и о них не знает. Глушение — хэндлерами вёрстки в состоянии «ввод»: `InputMapMuteHandler` (шина ввода), `NaniInputMuteHandler` (Naninovel)
- Разбор итога в тип значения (число и т.п.) — у владельца значения

## Использование

### Вёрстка

Рабочий пример — `ParameterItem` в `CheatConsole.prefab`:

```
ParameterItem                          ← UITextInput, владелец значения (HeroParameterTextInput)
├── [WriteModeSwitcher]                ← UIStateSwitcher: Off — пусто, On — включить Container и [InputHandler]
│   └── [InputHandler] (выкл.)         ← заглушки ввода
│       ├── InputMapMuteHandler ×N
│       ├── InputActionHandler ×N      ← (необязательно) перехват отдельных экшенов, исключённых из заглушки
│       └── NaniInputMuteHandler       ← если ввод бывает над Nani-сценой
├── Значение (текст)
├── InputBtn                           ← AdvancedButton → владелец значения → UITextInput.Begin(текст)
└── Container (выкл.)                  ← оверлей поверх значения; Button.onClick → UITextInput.Save или Rollback
    ├── cover                          ← подложка: клик поднимается к Button на Container
    ├── Background                     ← фон поверх значения
    └── Input                          ← TMP_InputField
```

- **`UITextInput` — на объекте, который не выключается свитчером**: выключение компонента во время ввода — откат. Объект поля может выключаться.
- **Свитчер:** `Off` — просмотр, `On` — ввод. На старте должен стоять `Off` (`stateOnEnable`). `GameObjectsSwitch` в состоянии `On` при переходе в `Off` выключает свои объекты сам — в `Off` пунктов не нужно.
- **Кнопка ввода** — `AdvancedButton`, а не `Button`: открывать ввод должен владелец значения через `Begin`, а не прямое переключение свитчера (иначе нет текста и фокуса).
- **Подложка** — кнопка на корне оверлея. Клик по самому полю перехватывает `TMP_InputField`, до подложки он не доходит.
- **`TMP_InputField`:** Line Type задаёт поведение Enter (см. ниже). Content Type / Character Validation не нужны — маску задают фильтры, а `onValidateInput` поля компонент занимает сам. «Выделить всё при фокусе» (включено по умолчанию) — первый же символ заменяет значение.

### Заглушки на время ввода

Включаются состоянием `On`, то есть после подписчиков, которых перекрывают (см. `InputBusSystem` → «Заглушка карты»).

| Карта | Что глушить | Исключения |
|---|---|---|
| `VirtualCursor` | Навигацию с клавиатуры: стрелки, Submit (Enter), Cancel (Esc) | **Позиция курсора, `Click`, `AltClick`, движение курсора с геймпада.** Курсор и клики идут через шину (`MouseInputDriver`, `ActionInputDriver`): заглушённые — курсор замирает, подложка и поле не нажимаются |
| `UI` | Всё — иначе Esc сработает в `UICancel` экрана (например, закроет консоль) | — |
| Naninovel | Не картой: Naninovel подписан на экшены в обход шины, `InputMapMuteHandler` на его карте ничего не глушит. Нужен `NaniInputMuteHandler` | — |

Экшен из исключений можно перехватить отдельно — `InputActionHandler` с пустыми событиями на том же слое: подписан позже, встаёт сверху.

### Код владельца значения

```csharp
[SerializeField] private UITextInput input;

private void OnEnable() => input.OnSave += OnSave;
private void OnDisable() => input.OnSave -= OnSave;

private void OnClick() => input.Begin(_data.Value.ToString(CultureInfo.InvariantCulture));
private void OnSave(string text) => _data.SetValue(int.Parse(text, CultureInfo.InvariantCulture));
```

Пример в проекте — `HeroParameterTextInput` (параметры героя в чит-консоли).

### Маска

Список `ITextInputFilter`. Строка допустима, только если её пропускают **все** фильтры.

| Фильтр | Во время набора | Итог |
|---|---|---|
| `IntegerRangeTextFilter` (min, max) | Цифры и минус в начале (если `min < 0`). Отсекается только то, что вставкой уже не исправить: число за границей в сторону роста модуля. «5» при `min = 10` допустимо — дальше могут идти цифры | Целое в диапазоне |
| `RegexTextFilter` (два выражения) | Выражение «во время набора» — должно принимать и недописанные строки (`^-?\d{0,3}$`) | Выражение «итог» (`^-?\d{1,3}$`) |

Выражения проверяют строку целиком, якоря `^…$` ставит автор. Пустое выражение пропускает любую строку.

Свой фильтр — `[Serializable]` класс с `ITextInputFilter`:

```csharp
bool IsValidPartial(string candidate);   // строка после вставки символа; false — символ не вводится
bool IsValidFinal(string text);          // false — сохранение не проходит, ввод продолжается
```

## Поведение

| Действие | Результат |
|---|---|
| `Begin(text)` | Откат ввода в другом поле, свитчер `On`, текст в поле, фокус. Во время ввода — заменить текст |
| Символ | `IsValidPartial` всех фильтров для строки после вставки; не прошёл — символ не вводится. Вставка из буфера проверяется посимвольно |
| Enter | `Save` (однострочное поле или многострочное с отправкой по Enter) |
| Esc | `Rollback` |
| `Save()` | `IsValidFinal` всех фильтров: не прошёл — ввод продолжается; прошёл — выход из ввода, затем `OnSave(text)` |
| `Rollback()` | Выход из ввода, затем `OnRollback` |
| Клик мимо поля | Поле теряет фокус, ввод не завершается — решает подложка |
| Выключение компонента во время ввода | Выход из ввода без событий |

Выход из ввода: снять фокус поля и выделение `EventSystem`, свитчер `Off`. Событие — **после** выхода: оверлей с заглушками уже выключен, когда владелец значения его меняет.

Enter по `Line Type` поля:
- `Single Line`, `Multi Line Submit` — Enter сохраняет;
- `Multi Line Newline` — Enter переносит строку; сохранение — только через `Save` из вёрстки.

## Граничные случаи

| Ситуация | Поведение |
|---|---|
| `Save` / `Rollback` вне ввода | Ничего (подложку можно линковать без условий) |
| `Begin` в другом поле во время ввода | Текущий ввод откатывается (`OnRollback`) |
| Итог не прошёл маску по Enter | Поле теряет фокус и получает его снова на следующем кадре; Esc после этого восстанавливает уже введённый текст, но ввод всё равно откатывается |
| Удаление символов | Не проверяется: промежуточная строка может не пройти `IsValidPartial`, итог проверяется при сохранении |
| Нет `EventSystem` | Фокус не ставится — ввода с клавиатуры нет |
| Нет фильтров | Пропускается любая строка |
