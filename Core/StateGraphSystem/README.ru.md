# StateGraphSystem (Core)

**Namespace:** `Vortex.Core.StateGraphSystem.Model`, `.Controllers`, `.Validation`
**Сборка:** `ru.vortex.stategraph`
**Платформа:** .NET Standard 2.1+

## Назначение

Универсальный конечный автомат: граф узлов и переходов, одна наблюдаемая переменная — текущий узел. Следующий узел выбирается по выполнению условий переходов (`Condition` из `LogicChainsSystem`) или по внешнему сигналу `Next`. Смысл узлов автомату неизвестен — его придаёт потребитель (показ катсцены, шаги UI, фазы боя и т. п.).

- Граф — запись БД `MultiInstance`: каждый потребитель берёт свою копию
- Переходы двух видов: автопереход (сам, как только выполнены условия) и переход «по `Next`»
- Приоритет переходов — порядок в узле; условия перехода — по И
- Конец — узел без переходов; событие `OnFinished`
- Принудительный переход `ForceNode` (по Id или имени) и принудительное завершение `Stop`
- Активность экземпляра: выключенный автомат игнорирует сигналы; режимы с сохранением состояния и без
- Проверка структуры графа — общая для рантайма и редактора

Вне скоупа:

- Показ, пресеты, визуальный редактор — Unity-слой (`ru.vortex.unity.stategraph`)
- Источник сигнала `Next` — его подаёт потребитель (кнопка, шина домена, сценарий)
- Сохранение состояния в сейв (`GetDataForSave()` → `null`)

## Использование

```csharp
var graph = Database.GetNewRecord<StateGraph>("graph-guid");   // своя копия
graph.CurrentNode.OnUpdate += id => Show(graph.GetNode(id)?.Name);
graph.OnFinished += Close;

graph.Activate();      // впервые — запуск со стартового узла
graph.Next();          // сигнал «дальше»
graph.ForceNode("Final");                     // по имени или Id
graph.Deactivate(retainState: true);          // пауза с сохранением состояния
graph.Stop();          // принудительное завершение
```

В Unity копию обычно держит `StateGraphView` и отдаёт её через `IDataStorage` (см. Unity-пакет).

## Модель

```
StateGraph : Record                       (MultiInstance)
├── Nodes        : StateNode[]
├── StartNode    : string                 ← Id стартового узла
├── CurrentNode  : StringData             ← Id текущего узла; пусто — не запущен / завершён (owner-lock)
├── InstanceId   : string                 ← владелец, которого получают условия (Condition.Init)
├── IsActive     : bool
└── OnFinished   : event Action

StateNode
├── Id           : string                 ← стабильный, на него ссылаются переходы
├── Name         : string                 ← уникальный ключ (по нему потребитель выбирает своё состояние)
├── NextMiss     : NextMissBehavior       ← Ignore (по умолчанию) / Warning / Error
└── Transitions  : StateTransition[]      ← порядок = приоритет

StateTransition
├── Target       : string                 ← Id узла-цели
├── WaitNext     : bool                   ← false — автопереход, true — по Next
└── Conditions   : Condition[]            ← по И; пусто — всегда выполнено
```

Логики в модели нет: всё меняет `StateGraphController` (методы-расширения). Свойства — `public get; internal set`.

## Исполнение

### Вход в узел

1. Запускаются условия **всех** переходов узла (`Condition.Init(callback, InstanceId)`), в том числе переходов «по `Next`» — условию вроде таймера нужно стартовать заранее.
2. Публикуется `CurrentNode`.
3. Проверяются автопереходы.

Сигнал условия, поданный синхронно из `Init`, не обрабатывается до запуска всех условий узла — иначе переход случился бы посреди запуска. Запоздалые сигналы условий прошлых входов отсекаются номером входа.

Вход в узел без переходов публикует его и сразу завершает автомат.

### Переходы

- **Автопереход** — при любом сигнале условия узла перепроверяются автопереходы по порядку; срабатывает первый с выполненными условиями.
- **По `Next`** — `Next()` выбирает первый по порядку переход «по `Next`» с выполненными условиями. Не нашлось — реакция по `NextMiss` узла (молча / предупреждение / ошибка в лог), узел не меняется.
- Переход: условия текущего узла останавливаются (`DeInit`), затем вход в целевой.

### Завершение

Естественное (вход в конечный узел) и принудительное (`Stop`) не различаются: условия останавливаются, `CurrentNode` пустеет, поднимается `OnFinished`.

### Активность

| Операция | Действие |
|---|---|
| `Activate()` | Впервые, после выключения без сохранения или после завершения — запуск со стартового узла. Иначе: узел, назначенный `ForceNode` в выключенном состоянии, входит сейчас; текущий узел перепроверяет автопереходы (условия могли выполниться за время простоя) |
| `Deactivate(true)` | Сохранить состояние (Resume): условия продолжают работать, переход откладывается до активации; принимаются только `ForceNode` (узел становится текущим и входит при активации) и `Stop` |
| `Deactivate(false)` | Без сохранения (Restart): условия останавливаются и сбрасываются; `CurrentNode` остаётся опубликованным до следующего запуска; сигналы игнорируются. Применим и к уже выключенному с сохранением экземпляру — так потребитель окончательно гасит условия |

Неактивный экземпляр игнорирует `Start`, `Next` и (без сохранения состояния) `ForceNode` / `Stop`.

### API

| Метод | Описание |
|---|---|
| `Activate()` / `Deactivate(bool retainState)` | Включение / выключение (см. «Активность») |
| `Start()` | Запуск или перезапуск со стартового узла (только активный) |
| `Next()` | Сигнал «дальше» |
| `ForceNode(string idOrName)` | Переход в узел минуя условия; на завершённом активном — запуск с этого узла |
| `Stop()` | Принудительное завершение; не запущенный — без действия |
| `GetNode(string id)` / `GetCurrentNode()` | Чтение узла |

## Проверка графа

`StateGraphValidator.Validate(nodes, startNode)` → список `StateGraphIssue` (тяжесть, вид, Id узла, номер перехода или -1, текст).

| Ошибки (`Error`) | Предупреждения (`Warning`) |
|---|---|
| `NoStartNode` — стартовый узел не задан или не найден | `UnreachableNode` — узел недостижим из стартового |
| `InvalidId` — пустой или повторяющийся Id | `ShadowedTransition` — переход после безусловного, никогда не выбирается |
| `EmptyName` — пустое имя (пустое значение — нейтральное значение показа) | |
| `DuplicateName` — повторяющееся имя | |
| `DanglingTarget` — переход на несуществующий узел | |
| `AutoCycle` — цикл из автопереходов | |

**Циклы.** Запрещены только циклы из автопереходов: они зациклили бы автомат без внешнего сигнала. Цикл, разорванный хотя бы одним переходом «по `Next`», допустим.

**Затенение.** Безусловный автопереход уводит из узла сразу — после него не выбирается ничего. Безусловный переход «по `Next`» забирает каждый `Next` — после него не выбирается ни один «по `Next`» (автопереходы — выбираются).

В рантайме граф проверяется один раз на экземпляр — при первом `Start` / `ForceNode`. С ошибками экземпляр не запускается, ошибки уходят в лог.

## Граничные случаи

| Ситуация | Поведение |
|---|---|
| Граф с ошибками | Ошибки в лог, экземпляр не запускается (защищает и от бесконечной рекурсии цикла автопереходов) |
| `Next` без подходящего перехода | По `NextMiss`: молча / `Warning` / `Error`; узел не меняется |
| `ForceNode` на неизвестный узел | `Error` в лог |
| Подписчик `CurrentNode` синхронно зовёт `Next` / `ForceNode` / `Stop` | Отрабатывает; прерванный вход дальше не выполняется |
| Условие сработало прямо в `Init` | Переход — после запуска всех условий узла |
| `Stop` на не запущенном | Без действия, `OnFinished` не поднимается |
| Простое выкл/вкл с сохранением | Продолжение с текущего узла без повторного входа |
| Включение после завершения | Запуск со стартового узла |
| Глубокая копия условий | Обеспечивает `Database` (`CopyFrom` → `DeepCopy`): у каждой копии свои экземпляры `Condition` |
