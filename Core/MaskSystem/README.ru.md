# MaskSystem (Core)

**Пространство имён:** `Vortex.Core.MaskSystem`
**Сборка:** `ru.vortex.core.masksystem`
**Платформа:** .NET Standard 2.1+

---

## Назначение

Правила сопоставления строк («маски»): ответ на вопрос «подходит ли строка под правило?» и, для части видов, извлечение именованных кусков строки. Совпадение всегда со **всей** строкой.

Возможности:

- `Mask` — абстрактное правило, заданное только операциями: проверка (`IsMatch`), сопоставление с захватами (`Match`), проверка своей настройки (`Validate`)
- `MatchResult` — признак совпадения и захваты «имя → значение» только для чтения
- `ValidationResult` — верность настройки, сообщение и позиция ошибки в шаблоне
- Три статических контроллера с логикой сопоставления каждого вида:
  - `StringEqualController` — строка равна образцу
  - `UrlController` — части адреса (схема, хост, порт, путь) соответствуют настройке
  - `RegexController` — строка соответствует регулярному выражению .NET
- Перечисления настроек: `StringCompareMode`, `TrimMode`, `SchemeCheckMode`, `HostCheckMode`, `PortCheckMode`, `PathCheckMode`

Вне зоны ответственности:

- Настройки масок и их хранение, подготовка входа (обрезка, нормализация, разбор URL) — Unity-пакет `ru.vortex.unity.masksystem`
- Порядок проверки списков масок и «первое совпадение» — ответственность держателя списка
- Обращение к сети: вид URL знает только синтаксис адреса

## Использование

Маски настраиваются в инспекторе через Unity-пакет. Потребитель проверяет свои маски при своей инициализации и останавливается на неверной:

```csharp
[SerializeReference] private Mask hostRule;

private void Init()
{
    var validation = hostRule.Validate();
    if (!validation.IsValid)
        throw new InvalidOperationException(validation.Message);
}

public bool IsPartnerHost(string url) => hostRule.IsMatch(url);
```

Захваты (вид regex):

```csharp
var result = mask.Match("api.partner.com/v2/x");
if (result.IsMatch && result.Captures.TryGetValue("ver", out var version))
    Log.Print(LogLevel.Common, $"Версия API {version}", this);
```

Контроллеры можно вызывать напрямую с подготовленными данными — например, для своего вида маски:

```csharp
var validation = RegexController.Validate(pattern);
var regex = RegexController.Build(pattern, ignoreCase: false);
var result = RegexController.Match(regex, input);
```

## Архитектура

```
Mask (abstract, [Serializable])
  ├── IsMatch(string) → bool
  ├── Match(string)   → MatchResult { IsMatch, Captures }
  └── Validate()      → ValidationResult { IsValid, Message, Position }

StringEqualController (static)
  ├── Validate(pattern, trimMode, compareMode, normalize)
  ├── FindInvalidUnicode(value) → индекс одиночного суррогата или -1
  └── IsMatch(ready, pattern, compareMode, ignoreCase)

UrlController (static)
  ├── ValidateScheme / ValidateHost / ValidatePort / ValidatePath, FirstInvalid(...)
  ├── ToIdnHost(host) → ASCII-форма проверенного хоста
  ├── IsSchemeMatch / IsHostMatch / IsPortMatch / IsPathMatch (над System.Uri)
  └── IsAll(scheme, host, port, path) → подошли все проверенные части

RegexController (static)
  ├── Validate(pattern)
  ├── Build(pattern, ignoreCase) → Regex с привязкой ко всей строке
  ├── IsMatch(regex, input)
  └── Match(regex, input) → MatchResult с захватами
```

Абстракция не хранит настроек. Конкретные классы масок (Unity-пакет) держат настройки, готовят вход и вызывают контроллер своего вида.

## Контракт

### `Mask`

1. `IsMatch(input)` равно `Match(input).IsMatch` для любой строки.
2. Нет совпадения ⇒ захваты пусты.
3. `input == null` — ошибка программиста.
4. Вход не изменяется.
5. До использования настройка проверяется через `Validate`; сопоставление на неверной настройке — ошибка программиста (fast-fail).

### Правила сопоставления

| Вид | Правило |
|---|---|
| Равенство строк | Подготовленный вход равен образцу. `Ordinal` — точное совпадение символов; `InvariantCulture` — по правилам инвариантной культуры (игнорируемые символы вроде U+200B, U+00AD не учитываются, канонически равные записи совпадают). Регистр — отдельный флаг. Пустой образец совпадает только с пустой строкой |
| URL | Сравниваются только проверяемые части; адрес подходит, если подошли все. Схема и хост — без учёта регистра. Хосты сравниваются в ASCII-форме (`IdnHost`, IDN — punycode). «Хост и поддомены» — по границе метки. Порт по умолчанию схемы равен явному. Путь — в экранированном виде; префикс — по границе сегмента. Query и фрагмент не проверяются |
| Regex | Синтаксис .NET, неявная привязка всего выражения (`\A(?:…)\z`), `CultureInvariant`. Именованные группы — ключ по имени, неименованные — по номеру; группа 0 и не участвовавшие группы не входят. Таймаута сопоставления нет |

### Проверка настройки

- Равенство строк: образец должен быть задан; пробельный символ на обрезаемом краю образца — ошибка (позиция — его индекс); при нормализации образец, который нельзя нормализовать, — ошибка.
- URL: значение должно совпадать со своей канонической формой в адресе (`System.Uri`); иначе сообщение подсказывает нужную форму. У хоста должна быть допустимая ASCII-форма, и он должен совпадать с ней или с её обратным Unicode-преобразованием. IP-адрес нельзя использовать в режиме «хост и поддомены». Порт 1–65535. Путь начинается с `/`.
- Regex: компилироваться должны и исходное выражение, и выражение с привязкой.
- Неизвестные значения перечислений — ошибка.

### Ошибки

| Ситуация | Поведение |
|---|---|
| Ошибка программиста или неверная настройка, переданная контроллеру | `Log.Print(Error)` + `ArgumentException` / `ArgumentNullException` / `ArgumentOutOfRangeException` |
| Входные данные, которые нельзя сопоставить (непарсящийся URL, невалидный Unicode, хост без допустимой ASCII-формы) | «не совпало», без исключения |

### Ограничения

| Ограничение | Причина |
|---|---|
| Только главный поток | Синхронизации нет |
| Без `RegexOptions.Compiled` | AOT-платформы (IL2CPP, WebGL) |
| Без сравнения в культуре устройства | Результат не должен зависеть от языка игрока |
| `ValidationResult` создают только контроллеры | Фабрики `internal` |

## Граничные случаи

| Ситуация | Поведение |
|---|---|
| Драйвер `Log` не подключён в момент fast-fail контроллера | `NullReferenceException` из `Log.Print` вместо исходного исключения |
| Regex с комментарием `#` в конце в режиме `x` | Ошибка проверки: комментарий поглощает закрывающую привязку; закройте комментарий переводом строки |
| `IsHostMatch` с хостом, полученным не через `ToIdnHost` | Сравнение может не сойтись: хосты сравниваются в ASCII-форме |
| Хост входа с символами, которые в ASCII-форме дают `;`, `,`, `|`, `%` или пробел | Не совпало |
| `file:///C:/x` на Windows | У `AbsolutePath` нет ведущего `/`; настройки пути «точно» и «префикс» до него не достают |
| Нестандартная схема (`foo://127.1/`) | `System.Uri` не приводит хост к канонической форме; настройка в канонической форме с ним не совпадёт |
