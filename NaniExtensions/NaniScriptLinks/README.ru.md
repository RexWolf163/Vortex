# NaniScriptLinks

**Сборки:** `ru.vortex.nani.script.links` (рантайм, контракт), `ru.vortex.nani.script.links.editor` (редактор, окно)
**Namespace:** `Vortex.NaniExtensions.NaniScriptLinks`

## Активация

Обе сборки — `defineConstraints: ["USING_NANINOVELL"]` (тоггл `naninovellExt` в `SdkSettings`). Источник квестов Vortex подключается только при `USING_VORTEX_QUESTS`; без него запуски — только из сценариев и настроек Naninovel.

## Назначение

Валидатор связей сценариев Naninovel: `Tools → Vortex → Debug → Nani Script Links`.

- **Сироты** — сценарии без входящих связей извне: их не запускает ни квест, ни настройки Naninovel, и в них не переходит ни один другой сценарий. Группировка по папкам.
- **Неиспользуемые метки** — метки, на которые не ведёт ни один переход (включая переходы своего сценария).
- **Битые ссылки** — нет сценария; нет метки; цель совпадает с существующей только без учёта регистра; метка объявлена в сценарии дважды; логика квеста ссылается на удалённый ассет сценария.
- **Проблемы** — что не удалось прочитать или разрешить: файл `.nani` вне реестра, запись реестра без файла, логика-запуск без сценария, цель-выражение, ненужное исключение.
- **Исключения** — осознанно незапускаемые сценарии и метки, с причиной.

Клик по месту открывает сценарий на строке во внешнем редакторе или выделяет ассет (пресет квеста, настройки Naninovel); кнопка **Find** у каждой строки выделяет файл места в инспекторе и подсвечивает в окне Project. Длинные места и сообщения переносятся по строкам — горизонтальной прокрутки нет. Работает без запуска игры. Ассеты проекта инструмент не меняет — пишутся только исключения.

Вне ответственности:
- Сцены, префабы и прочие ScriptableObject не сканируются: сценарии, которые запускаются только оттуда (`MiniGameStarter`, галерея, чит-консоль), попадут в сироты — их закрывают исключениями.
- Достижимость самого квеста не проверяется: сценарий квеста, который никогда не активируется, считается достижимым.
- Условия переходов (`if:`) не вычисляются: условный переход — такая же связь.
- Окна `NarrativeImportTool` и Script Graph Naninovel не затрагиваются.

## Зависимости

- Naninovel — `Script` и его строки (`LabelScriptLine`, `CommandScriptLine`, `GenericTextScriptLine`), `EndpointContextAttribute`, `NamedStringParameter`, `ScriptsConfiguration`, `EditorResources`
- Редактор Unity — `AssetDatabase`, `SerializedObject`, `ScriptableSingleton`
- Квесты Vortex — только по имени типа пресета (`t:QuestPreset`); ссылки на сборку квестов нет

## Использование

### Сборка карты

Кнопка «Собрать». Сборка читает реестр сценариев Naninovel, все сценарии реестра, все пресеты квестов и стартовые сценарии настроек; индикатор прогресса с отменой. Карта живёт только в памяти: сбрасывается при перекомпиляции и при входе в Play Mode. Изменения ассетов после сборки не отслеживаются — ориентир актуальности время сборки в окне. Правка исключений применяется сразу, без пересборки.

### Подключение логики квеста, запускающей сценарий

Объект квеста, который запускает сценарий, реализует `INaniScriptLaunch` — иначе валидатор его не видит, и сценарий может оказаться в сиротах:

```csharp
[Serializable]
public class RunNaniScript : QuestLogic, INaniScriptLaunch
{
    [SerializeField] private Script naninovelScript;

    string INaniScriptLaunch.ScriptPath => naninovelScript != null ? naninovelScript.Path : null;
    // ...
}
```

Объект, который только ссылается на сценарий (`WaitStopNaniScript` — ждёт окончания), контракт не реализует: ссылка ≠ запуск. Контракт поведение в игре не меняет. Сейчас его реализует `RunNaniScript` (пакет [QuestSystem](../QuestSystem/), `Vortex.NaniExtensions.QuestSystem.Logics`).

### Исключения

Настройки проекта: `ProjectSettings/NaniScriptLinks.asset` (в контроле версий, общий для команды). Запись — цель и причина (обязательна). Цель — путь реестра:

| Цель | Пример | Что выводит из анализа |
|------|--------|------------------------|
| Папка (оканчивается на `/`) | `DEBUG/` | Все сценарии под путём вместе с их метками |
| Сценарий | `DLC1/GYMIntro` | Сценарий вместе с его метками |
| Метка | `DLC1/GYMIntro.play` | Только эту метку |

Исключение действует на «Сироты» и «Неиспользуемые метки»; битые ссылки не исключаются — их исправляют. Кнопки «Исключить» и «Исключить папку» переносят цель в форму вкладки «Исключения», где вводится причина. Исключение, которое ничего не скрывает (под ним нет точек входа или у всех есть входящие связи), показывается в «Проблемах» как ненужное.

## Архитектура

```
NaniScriptLinks/
├── INaniScriptLaunch.cs               ← контракт «запускает сценарий» (рантайм)
└── Editor/
    ├── NaniScriptLinksWindow*.cs      ← окно: Сироты / Неиспользуемые метки / Битые ссылки / Проблемы / Исключения
    ├── Model/
    │   ├── LinkModels.cs              ← места, связь, сценарий и метка (точки входа), битая ссылка, проблема
    │   ├── LinkIndex.cs               ← карта (Current — static, память)
    │   ├── LinkAnalysis.cs            ← сироты, неиспользуемые метки, ненужные исключения (кэш по карте и ревизии исключений)
    │   └── ScriptLinksSettings.cs     ← исключения (ScriptableSingleton в ProjectSettings)
    └── Sources/
        ├── LinkIndexBuilder.cs        ← сборка и Rebuild: реестр → сценарии → квесты → настройки → разрешение связей
        ├── ScriptSource.cs            ← реестр и разбор скомпилированных сценариев
        └── QuestSource.cs             ← обход пресетов квестов (USING_VORTEX_QUESTS)
```

Зависимости однонаправленные: окно → сборщик и источники → модель. Модель не знает ни сборщика, ни источников. Окно только показывает карту; сборку запускает сборщик, исключения меняют только методы настроек. Место связи или находки (`LinkLocation`) полиморфно: `Describe` (подпись), `Open` (переход: сценарий — на строке, остальное — выделить), `Find` (выделить файл в инспекторе).

### Точки входа и достижимость

Индекс точек входа: `{сценарий}` (начало) и `{сценарий}.{метка}` — каждая со списком входящих связей. Точки создаются только из реестра и объявленных меток; связь, не нашедшая точку, — битая ссылка.

- **Сценарий** достижим, если у него есть хотя бы одна входящая связь извне — из другого сценария, квеста или настроек — на начало или на любую метку. Связь сценария на самого себя (`.Label`, `@goto <свой путь>`) достижимости не даёт. Достижимость прямая: два сценария, ссылающиеся только друг на друга, оба достижимы.
- **Метка** используется, если на неё есть хотя бы одна связь, включая переход из своего сценария.
- Состояние проверяется по порядку: «есть входящие» → «исключена» → «сирота / неиспользуемая метка».

### Источники связей

| Источник | Что даёт связь |
|----------|----------------|
| Сценарии | Каждый параметр команды с `EndpointContextAttribute` — `@goto`, `@gosub`, `goto:` / `gosub:` у `@choice`; команды в строках текста (`[goto …]`) — так же. Команды проекта с этим атрибутом подхватываются без правки валидатора |
| Квесты | Каждый объект пресета (на любой глубине), реализующий `INaniScriptLaunch` |
| Настройки Naninovel | Заданные `InitializationScript`, `TitleScript`, `StartGameScript` |

Сценарии читаются из скомпилированного ассета — того же разбора, по которому играет Naninovel: отступы внутри `@if`/`@choice`, `if:`, `release!` учтены им. Цель `.Label` дополняется путём своего сценария.

## Контракт

### Вход
- Реестр ресурсов Naninovel (категория сценариев), ассеты сценариев, ассеты `QuestPreset`, `ScriptsConfiguration`
- Объекты квеста, реализующие `INaniScriptLaunch`

### Выход
- Окно; запись — только исключения в `ProjectSettings`

### Гарантии
- Сборка заменяет карту целиком или не меняет её (отмена — прежняя карта)
- Каждая принятая связь — ровно в одной точке входа; не принятая — ровно одна битая ссылка
- Сопоставление — только по полному пути реестра и метке, с учётом регистра; имена файлов не используются (одинаковые имена в разных папках — разные сценарии)
- Сироты, неиспользуемые метки и ненужные исключения вычисляются при показе из текущей карты и исключений, нигде не хранятся
- Ошибка одного ассета не обрывает сборку

### Ограничения
- Карта не отслеживает изменения ассетов; пересборка — вручную
- Цель-выражение (`{…}`) статически не разрешается — проблема сборки, не связь
- Удалённый ассет в логике квеста распознаётся по сериализованной ссылке на ассет сценария внутри объекта (идентификатор есть, объекта нет); если не распознан — «логика-запуск без сценария» в «Проблемах»
- Имя типа пресета (`t:QuestPreset`) зашито в источник квестов. Поломка шва громкая: пресетов не найдено — проблема сборки

## Граничные случаи

| Ситуация | Поведение |
|----------|-----------|
| Карта не собрана | Подсказка и кнопка «Собрать»; вкладка «Исключения» работает |
| Вход в Play Mode, перекомпиляция | Карта сброшена, собрать заново |
| `@goto .Label` на необъявленную метку | Битая ссылка «нет метки» |
| `@goto Script` на сценарий, которого нет в реестре | Битая ссылка «нет сценария» |
| Цель отличается от существующей только регистром | Битая ссылка «регистр» с подсказкой правильного написания |
| Метка объявлена дважды | Битая ссылка «дубль метки» на втором объявлении; переходы засчитываются метке |
| `StartGameScript` указывает на несуществующий путь | Битая ссылка «нет сценария» с местом в настройках |
| Файл `.nani` вне реестра (вне Scenario Root) | Проблема; переходы на него — битые ссылки |
| Запись реестра без файла | Проблема с местом в реестре ресурсов |
| Логика-запуск без сценария | Проблема |
| Логика-запуск на удалённый ассет | Битая ссылка «удалён ассет» |
| Битая ссылка на тип в пресете | Проблема с именем типа |
| Исключение при разборе сценария или обходе пресета | Проблема, остальное собирается |
| Пресеты квестов не найдены при включённых квестах | Проблема сборки: переименован тип пресета |
| Клик или Find по ассету, перемещённому после сборки | Предупреждение в консоль |
| Место без файла (пресеты квестов не найдены) | Find недоступна |
| Исключение, под которым ничего нет / всё достижимо | Проблема «ненужное исключение» |
| Исключение с пустой целью или причиной | Не добавляется |
| Повторное исключение на ту же цель | Обновляет причину |
| `USING_VORTEX_QUESTS` выключен | Квесты не сканируются; в сводке «квесты Vortex отключены» |
